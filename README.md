# سامانه ساده‌ی ثبت خودکار پلاک و هشدار عبور (LPR / ALPR + Line Crossing)

این پروژه یک دوربین معمولی یا دوربین مداربسته‌ی موجود را به یک سامانه‌ی
ثبت خودکار پلاک و هشدار عبور از خط/محدوده، با **رابط گرافیکی کاربرپسند**
تبدیل می‌کند — بدون نیاز به کار با خط فرمان. کاربر با چند کلیک دوربین
اضافه می‌کند، پایش را شروع می‌کند و گزارش تردد را می‌بیند.

## قابلیت‌ها
**تشخیص پلاک:**
- دریافت تصویر زنده از وبکم، فایل ویدیویی یا استریم RTSP
- تشخیص ناحیه‌ی احتمالی پلاک در فریم (ترکیب Haar Cascade و روش کلاسیک لبه‌یابی)
- خواندن متن پلاک با OCR (پشتیبانی از حروف و اعداد فارسی)
- قالب‌بندی و اعتبارسنجی پلاک مطابق الگوی رایج ایران (مثل `12ب345-67`)
- ثبت خودکار در دیتابیس SQLite و فایل CSV، همراه با عکس برش پلاک

**هشدار عبور از خط/محدوده (ویژگی جدید):**
- رسم یک خط یا یک محدوده‌ی بسته (چندضلعی) روی عکس هر دوربین، مستقیماً در رابط گرافیکی
- انتخاب این‌که نسبت به عبور چه چیزی حساس باشد: فرد، حیوان، خودرو، موتورسیکلت، اتوبوس، کامیون/تریلی، دوچرخه
- تشخیص خودکار اشیاء با یک مدل سبک (YOLOv4-tiny) و ردیابی آن‌ها بین فریم‌ها برای فهمیدن لحظه‌ی دقیق عبور
- گرفتن عکس از صحنه در لحظه‌ی عبور و ثبت آن به همراه تاریخ، ساعت، نوع شیء و نام ناحیه در دیتابیس
- گزارش‌گیری و فیلتر جداگانه برای رویدادهای عبور (تب «گزارش عبور»)

**عمومی:**
- پایش هم‌زمان چند دوربین
- جلوگیری از ثبت تکراری یک پلاک/رویداد در بازه‌ی زمانی کوتاه
- نمایش زنده‌ی تصویر با کادر دور پلاک/اشیاء و خطوط هشدار تعریف‌شده
- کاملاً قابل اجرا به‌صورت آفلاین (بدون اینترنت) پس از دانلود یک‌باره‌ی مدل‌ها

## عیب‌یابی: خطای «is not recognized as an internal or external command»

اگر هنگام اجرای فایل‌های `.bat` با پیام‌هایی مثل بالا مواجه شدید، دلیلش
ناسازگاری `cmd.exe` ویندوز با متن فارسی/یونیکد و دستورات چندخطی داخل
فایل batch بود. این مشکل در نسخه‌ی فعلی برطرف شده: تمام فایل‌های `.bat`
اکنون کاملاً انگلیسی و تک‌خطی هستند، و کار ساخت میانبر (که نیاز به نام
فارسی دارد) به یک اسکریپت جداگانه‌ی PowerShell (`make_shortcut.ps1`)
منتقل شده که یونیکد را درست پشتیبانی می‌کند. کافی است فایل‌های جدید را
جایگزین نسخه‌ی قبلی کنید و دوباره اجرا کنید.

## عیب‌یابی: «No such file or directory: requirements.txt» یا «No module named 'cv2'»

این خطا زمانی رخ می‌دهد که `install_windows.bat` با «Run as Administrator»
اجرا شده باشد؛ در آن حالت ویندوز پوشه‌ی شروع را به `C:\Windows\System32`
تغییر می‌دهد و محیط مجازی (`venv`) به‌اشتباه آنجا ساخته می‌شود، نه داخل
پوشه‌ی پروژه. نسخه‌ی فعلی این مشکل را برطرف کرده (با انتقال خودکار به
پوشه‌ی خودِ فایل bat در همان ابتدا). اگر این خطا را قبلاً دیده‌اید:

1. فایل `install_windows.bat` جدید را جایگزین نسخه‌ی قبلی کنید.
2. اگر پوشه‌ی `C:\Windows\System32\venv` به‌اشتباه ساخته شده، آن را حذف
   کنید (یک پوشه‌ی معمولی است که خودِ اسکریپت اشتباهاً آنجا ساخته، جزئی
   از خود ویندوز نیست و حذفش بی‌خطر است). برای این کار Command Prompt را
   با دسترسی Administrator باز کرده و دستور زیر را بزنید:
   ```
   rmdir /s /q C:\Windows\System32\venv
   ```
3. اگر پوشه‌ی `venv` داخل خود پوشه‌ی پروژه هم از تلاش‌های قبلی نیمه‌کاره
   مانده، آن را هم حذف کنید تا از نو و تمیز ساخته شود.
4. این بار `install_windows.bat` را بدون «Run as Administrator» (با
   دوبار کلیک ساده) اجرا کنید؛ برای این برنامه نیازی به دسترسی ادمین نیست.

## ساخت نصب‌کننده‌ی ویندوز با گیت‌هاب (بدون نیاز به سیستم ویندوزی شخصی)

اگر سیستم ویندوزی برای ساخت exe در اختیار ندارید، می‌توانید از
**GitHub Actions** استفاده کنید: گیت‌هاب به‌صورت رایگان یک ماشین ویندوزی
موقت راه‌اندازی می‌کند، پروژه را می‌سازد، و فایل نهایی را برای دانلود
آماده می‌کند. فایل تنظیمات آن (`.github/workflows/build-windows.yml`)
از قبل در پروژه آماده است؛ کافیست:

1. **ساخت مخزن (Repository) در گیت‌هاب**: وارد [github.com](https://github.com) شوید
   (یا ثبت‌نام کنید)، دکمه‌ی «New repository» را بزنید، یک نام بدهید
   (مثلاً `lpr-system`) و آن را بسازید (Public یا Private، هر دو مشکلی ندارد).

2. **آپلود کد پروژه به آن مخزن**. دو راه دارید:
   - **بدون خط فرمان**: در صفحه‌ی مخزن، روی «Add file → Upload files»
     کلیک کنید و همه‌ی فایل‌های این پوشه (شامل پوشه‌ی مخفی `.github`) را
     بکشید و رها کنید، سپس «Commit changes» را بزنید.
     > نکته: فایل‌های داخل `.github/workflows/` باید دقیقاً با همین
     > مسیر آپلود شوند تا گیت‌هاب آن‌ها را به‌عنوان Workflow بشناسد؛
     > اگر رابط وب مشکلی در حفظ ساختار پوشه داشت، از روش زیر (git) استفاده کنید.
   - **با خط فرمان** (git از قبل روی سیستم نصب باشد):
     ```bash
     cd lpr_system
     git init
     git add .
     git commit -m "نسخه اولیه"
     git branch -M main
     git remote add origin https://github.com/USERNAME/lpr-system.git
     git push -u origin main
     ```

3. **اجرای خودکار ساخت (Build)**: به محض push شدن کد، گیت‌هاب خودش
   شروع به ساخت می‌کند. برای دیدن وضعیت، در صفحه‌ی مخزن روی تب
   **«Actions»** بروید؛ یک اجرا با نام «Build Windows Installer» می‌بینید
   (چند دقیقه طول می‌کشد). اگر می‌خواهید بدون push جدید هم دوباره بسازید،
   همان‌جا روی workflow کلیک کرده و دکمه‌ی **«Run workflow»** را بزنید.

4. **دانلود فایل نهایی**: پس از اتمام (علامت ✓ سبز)، روی همان اجرا کلیک
   کنید؛ در پایین صفحه، بخش **«Artifacts»** دو فایل zip می‌بینید:
   - `LPR-Camera-System-exe` → فایل اجرایی مستقل (تک‌فایلی)
   - `LPR-Setup-installer` → نصب‌کننده‌ی کامل ویندوز (`LPR-Setup.exe`) با
     میانبر دسکتاپ و امکان Uninstall
   
   هرکدام را دانلود و از حالت zip خارج کنید تا فایل exe داخلش را داشته باشید.

> این روش کاملاً رایگان است (گیت‌هاب برای مخازن عمومی و همچنین با سهمیه‌ی
> رایگان ماهانه برای مخازن خصوصی، اجرای Actions روی ویندوز را پشتیبانی
> می‌کند) و هر بار که کد را به‌روزرسانی و push کنید، نسخه‌ی جدید exe
> به‌صورت خودکار دوباره ساخته می‌شود.

## استفاده کاملاً آفلاین (بدون اینترنت حتی در اولین اجرا) — انتقال با فلش

به‌صورت پیش‌فرض، در اولین اجرا کتابخانه‌ی OCR مدل‌های تشخیص حروف را از
اینترنت دانلود می‌کند (و اگر خط/محدوده‌ی هشدار هم تعریف کرده باشید، مدل
تشخیص اشیاء هم همین‌طور). اگر سیستم مقصد (مثلاً کامپیوتر داخل سایت
کارگاهی) اصلاً اینترنت ندارد، دو راه دارید:

### راه ۱ (پیشنهادی): نصب‌کننده‌ی گیت‌هاب از قبل مدل‌ها را همراه دارد
Workflow گیت‌هاب (`.github/workflows/build-windows.yml`) طوری تنظیم شده
که پیش از ساخت exe، هم مدل‌های OCR و هم مدل تشخیص اشیاء را خودش دانلود
و **داخل نصب‌کننده‌ی نهایی (`LPR-Setup.exe`) جاسازی می‌کند**. یعنی اگر
همین workflow را (طبق راهنمای قبلی) در گیت‌هاب اجرا کرده باشید، فایل
`LPR-Setup-installer` که از تب Artifacts دانلود می‌کنید از قبل کامل
است — نصب‌کننده را با فلش به سیستم مقصد (حتی بدون اینترنت) منتقل کنید،
نصب کنید، و همان‌جا اجرا کنید؛ دیگر نیازی به اینترنت در هیچ مرحله‌ای نیست.

> اگر workflow را قبل از این تغییر اجرا کرده بودید، کافی است دوباره کد
> جدید را در گیت‌هاب push/آپلود کنید تا یک بار دیگر Actions اجرا شود و
> این بار نصب‌کننده‌ی جدید شامل مدل‌ها باشد.

### راه ۲: دانلود دستی مدل‌ها روی یک سیستم دیگر
اگر می‌خواهید بدون گیت‌هاب و به‌صورت محلی این کار را انجام دهید:

1. روی یک سیستم **متصل به اینترنت** که پروژه و `venv` روی آن نصب است، دستورهای زیر را اجرا کنید:
   ```bash
   python download_models.py
   python download_yolo_model.py
   ```
   این دستورها دو پوشه‌ی جدید به نام‌های `easyocr_models` و `yolo_model`
   کنار بقیه‌ی فایل‌های پروژه می‌سازند و مدل‌های لازم را در آن‌ها دانلود
   می‌کنند (رویهم چند صد مگابایت).

2. هر دو پوشه‌ی `easyocr_models` و `yolo_model` را با فلش به سیستم مقصد
   منتقل کنید، **دقیقاً کنار همان فایل exe یا کنار همان `gui_app.py`**
   که آنجا اجرا می‌کنید (هم‌سطح، نه داخل یک زیرپوشه‌ی دیگر).

3. برنامه را اجرا کنید؛ چون پوشه‌ی مدل‌ها از قبل پر است، هیچ دانلودی
   انجام نمی‌شود و همه‌چیز آفلاین کار می‌کند.

> نکته‌ی فنی: مسیر پوشه‌ی مدل‌ها همیشه «کنار خودِ فایل اجراشونده» محاسبه
> می‌شود (چه فایل exe باشد، چه `gui_app.py`)، نه در پوشه‌ی کاربر ویندوز؛
> پس همیشه باید این پوشه دقیقاً هم‌سطح با فایل اجراشونده باشد.

## نصب سریع (ویندوز) — برای کاربر نهایی

1. پوشه‌ی پروژه را روی سیستم کپی کنید.
2. روی فایل **`install_windows.bat`** دوبار کلیک کنید (اولین بار).
   - اگر پیام «پایتون نصب نیست» دیدید، اول Python 3.10+ را از
     [python.org](https://www.python.org/downloads/) نصب کنید و حتماً
     تیک **Add Python to PATH** را در حین نصب بزنید، سپس دوباره
     `install_windows.bat` را اجرا کنید.
   - این اسکریپت به‌صورت خودکار کتابخانه‌های لازم را نصب می‌کند و یک
     میانبر روی دسکتاپ با نام «سامانه ثبت پلاک» می‌سازد.
3. از این پس فقط روی میانبر دسکتاپ (یا فایل `run.bat`) دوبار کلیک کنید تا برنامه باز شود.

> نکته: `install_windows.bat` باید فقط **یک بار** اجرا شود؛ اجراهای بعدی
> فقط از طریق `run.bat` یا میانبر دسکتاپ است.

## ساخت یک نصب‌کننده‌ی واقعی (Setup.exe) برای توزیع به کاربران دیگر

اگر می‌خواهید برنامه را روی چند سیستم دیگر نصب کنید و نمی‌خواهید هر بار
پایتون/کتابخانه‌ها را جداگانه نصب کنید، می‌توانید یک فایل نصب‌کننده‌ی
تک‌فایلی مثل هر نرم‌افزار دیگر ویندوز بسازید:

1. روی همان سیستمی که `install_windows.bat` را اجرا کرده‌اید (تا `venv`
   و کتابخانه‌ها آماده باشند)، فایل **`build_standalone_exe.bat`** را
   اجرا کنید. این کار یک فایل مستقل `dist\LPR-Camera-System.exe` می‌سازد
   که برای اجرا نیازی به نصب پایتون روی سیستم مقصد ندارد.
2. نرم‌افزار رایگان [Inno Setup](https://jrsoftware.org/isinfo.php) را نصب کنید.
3. فایل **`installer.iss`** را با Inno Setup باز و کامپایل (Build) کنید.
4. خروجی نهایی `LPR-Setup.exe` را به هر سیستم دیگری کپی کنید؛ کاربر با
   دوبار کلیک روی آن، برنامه را دقیقاً مثل نرم‌افزارهای دیگر نصب می‌کند
   (میانبر دسکتاپ، آیتم در منوی استارت، امکان Uninstall).

> این دو مرحله (ساخت exe و نصب‌کننده) باید روی خود ویندوز انجام شوند،
> چون ابزار بسته‌بندی (PyInstaller) فقط برای همان سیستم‌عاملی که رویش
> اجرا می‌شود خروجی می‌سازد.

## نصب روی لینوکس/مک

```bash
./run.sh
```
اولین اجرا به‌صورت خودکار محیط مجازی و کتابخانه‌ها را نصب می‌کند.

## استفاده از برنامه (رابط گرافیکی)

پس از باز شدن برنامه، سه تب می‌بینید:

### تب «دوربین‌ها»
- روی **«افزودن دوربین»** کلیک کنید.
- یک نام دلخواه بدهید (مثلاً «ورودی اصلی سایت»).
- نوع منبع را انتخاب کنید:
  - **دوربین مداربسته (RTSP)**: آدرس دوربین را وارد کنید (راهنما زیر).
  - **وبکم سیستم**: عدد `0` را وارد کنید (یا `1`، `2` برای وبکم‌های بعدی).
  - **فایل ویدیویی**: برای تست، با دکمه‌ی «انتخاب فایل...» یک ویدیو انتخاب کنید.
- قبل از ذخیره، روی **«تست اتصال»** بزنید تا مطمئن شوید آدرس درست است.
- **«ذخیره»** را بزنید، سپس دوربین را در لیست انتخاب کرده و **«▶ شروع پایش»** را بزنید.
- برای توقف، دوربین را انتخاب و **«■ توقف پایش»** را بزنید.

می‌توانید هم‌زمان چند دوربین اضافه کرده و همه را پایش کنید.

### تب «نمایش زنده»
از منوی کشویی بالا، دوربینِ در حال پایش موردنظر را انتخاب کنید تا تصویر
زنده‌ی آن (با کادر سبز دور پلاک‌های شناسایی‌شده، کادر نارنجی دور اشیاء
ردیابی‌شده، و خط/محدوده‌ی نارنجی‌رنگِ تعریف‌شده) نمایش داده شود. لیست
سمت چپ آخرین پلاک‌ها و رویدادهای عبور (با علامت ⚠) را نشان می‌دهد.

### تب «خط/محدوده هشدار» (تشخیص عبور فرد/حیوان/خودرو و غیره)
این تب برای تعریف این‌که «چه چیزی از کجای تصویر رد شود هشدار داده شود»:

1. یک دوربین را از لیست کشویی بالا انتخاب کنید.
2. روی **«تعریف خط/محدوده‌ی جدید»** کلیک کنید؛ یک عکس نمونه از همان دوربین گرفته می‌شود.
3. روی عکس، با **کلیک چپ** نقاط خط یا محدوده را به ترتیب مشخص کنید (کلیک راست، آخرین نقطه را حذف می‌کند):
   - برای یک **خط ساده** (مثل خط مورب وسط پیاده‌رو/درایوی که هرکس از آن رد شود هشدار بدهد)، فقط چند نقطه بزنید و تیک «محدوده‌ی بسته» را نزنید.
   - برای یک **محدوده‌ی بسته** (مثل کل ایوان یا حیاط پشتی)، حداقل ۳ نقطه بزنید و تیک «محدوده‌ی بسته (چندضلعی)» را بزنید؛ خط‌چین نشان می‌دهد شکل چطور بسته می‌شود.
4. از چک‌باکس‌های پایین، انتخاب کنید نسبت به عبور چه چیزی هشدار داده شود: **فرد، حیوان، خودرو، موتورسیکلت، اتوبوس، کامیون/تریلی، دوچرخه** (پیش‌فرض: فرد و خودرو تیک خورده‌اند).
5. یک نام برای ناحیه بگذارید (مثلاً «ورودی حیاط») و **«ذخیره»** را بزنید.

از این پس، وقتی پایش آن دوربین را شروع کنید، هر بار یکی از دسته‌های
انتخاب‌شده از آن خط/محدوده عبور کند، یک عکس از صحنه گرفته می‌شود و به
همراه تاریخ، ساعت، نوع شیء و نام ناحیه در دیتابیس ثبت می‌شود (تب «گزارش عبور»).

> برای فعال شدن این قابلیت، باید یک‌بار مدل تشخیص اشیاء دانلود شود —
> بخش «دانلود مدل تشخیص اشیاء» را در ادامه‌ی همین راهنما ببینید. اگر
> برای دوربینی خط/محدوده تعریف کنید ولی مدل دانلود نشده باشد، تشخیص پلاک
> طبق معمول کار می‌کند ولی تشخیص عبور غیرفعال می‌ماند (یک پیام هشدار هم
> در همان لحظه به شما نشان داده می‌شود).

می‌توانید برای هر دوربین چند خط/محدوده‌ی جداگانه (با دسته‌های متفاوت)
تعریف کنید. برای حذف یک ناحیه، آن را در جدول انتخاب کرده و «حذف
ناحیه‌ی انتخاب‌شده» را بزنید (اگر پایش آن دوربین روشن است، یک بار
متوقف و دوباره شروع کنید تا تغییر اعمال شود).

### تب «گزارش پلاک‌ها»
تمام ترددهای ثبت‌شده در جدول نمایش داده می‌شوند: تاریخ/ساعت، دوربین،
پلاک و میزان اطمینان. می‌توانید بر اساس تاریخ، پلاک یا نام دوربین فیلتر
کنید. با **دوبار کلیک** روی هر ردیف، عکس همان تردد (نمای کامل صحنه) باز
می‌شود.

### تب «گزارش عبور»
تمام رویدادهای عبور از خط/محدوده ثبت‌شده را نشان می‌دهد: تاریخ/ساعت،
دوربین، ناحیه، نوع شیء (فرد/حیوان/خودرو/...) و میزان اطمینان. مثل تب
قبلی، قابل فیلتر است و با دوبار کلیک روی هر ردیف، عکس همان لحظه باز
می‌شود.

## دانلود مدل تشخیص اشیاء (برای قابلیت خط/محدوده هشدار)

قابلیت تشخیص عبور فرد/حیوان/خودرو از یک مدل سبک و رایگان به نام
**YOLOv4-tiny** استفاده می‌کند که باید یک‌بار دانلود شود:

```bash
python download_yolo_model.py
```

این دستور یک پوشه‌ی جدید به نام `yolo_model` (حدود ۲۵ مگابایت) کنار
بقیه‌ی فایل‌های برنامه می‌سازد. اگر از روش گیت‌هاب (بخش قبلی همین
راهنما) برای ساخت نصب‌کننده استفاده کرده باشید، این مدل از قبل همراه
با مدل‌های OCR داخل نصب‌کننده جاسازی شده و نیازی به این کار دستی
نیست. برای انتقال با فلش هم دقیقاً مثل پوشه‌ی `easyocr_models`، کافی
است پوشه‌ی `yolo_model` را هم کنار فایل exe یا `gui_app.py` بگذارید.

## آدرس RTSP دوربین مداربسته‌ی موجود در سایت

معمولاً در تنظیمات شبکه‌ی DVR/NVR یا دفترچه‌ی راهنمای دستگاه آمده. فرمت رایج:
- Hikvision: `rtsp://USER:PASS@IP:554/Streaming/Channels/101`
- Dahua: `rtsp://USER:PASS@IP:554/cam/realmonitor?channel=1&subtype=0`
اگر برند دیگری دارید، نام برند + "RTSP URL format" را جست‌وجو کنید.

## کالیبراسیون تشخیص عبور خودرو

چون دوربین مداربسته ۲۴ ساعته روشن است، سامانه فقط وقتی جسم بزرگی
(خودرو) در کادر حرکت کند OCR را اجرا می‌کند (فایل `motion_trigger.py`).
دو مقدار در `config.py` را متناسب با زاویه/فاصله‌ی دوربین خودتان تنظیم کنید:
- `MIN_VEHICLE_MOTION_AREA`: هرچه دوربین دورتر باشد، این عدد را کمتر کنید.
- `DETECTION_ROI`: برای محدود کردن ناحیه‌ی نظارت فقط به باند تردد (جلوگیری از ثبت اشتباه به‌خاطر عابر/سایه).

## نصب دستی و استفاده از خط فرمان (برای توسعه‌دهندگان)

اگر ترجیح می‌دهید بدون رابط گرافیکی و از طریق خط فرمان کار کنید (مثلاً
برای اجرا روی یک سرور بدون مانیتور)، همان قابلیت‌ها با `main.py` هم در
دسترس است:

```bash
cd lpr_system
python3 -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt

# اجرا با وبکم پیش‌فرض
python main.py

# اجرا با دوربین مداربسته (RTSP)
python main.py --source "rtsp://user:pass@192.168.1.10:554/stream1" --no-display

# مشاهده‌ی گزارش از خط فرمان
python report.py --date 2026-09-25
```

> نکته: نصب `easyocr` مدل‌های OCR را در اولین اجرا دانلود می‌کند (چند صد
> مگابایت)، پس اولین بار به اینترنت نیاز دارید.

خروجی‌ها (چه از رابط گرافیکی و چه از خط فرمان) در پوشه‌ی `output/` ذخیره می‌شوند:
- `output/plates_log.db` — دیتابیس SQLite با جدول `plates`
- `output/plates_log.csv` — همان اطلاعات به‌صورت CSV
- `output/plates/` — عکس نمای نزدیک هر پلاک
- `output/vehicles/` — عکس کامل صحنه/خودرو

## تنظیم برای پلاک غیر ایرانی / فرمت دیگر

اگر می‌خواهید روی فرمت پلاک کشور دیگری کار کنید، فقط کافی است:
1. الگوی `PLATE_PATTERN` در `utils.py` را با فرمت مدنظرتان جایگزین کنید.
2. در صورت نیاز، زبان OCR را در `config.py` (`OCR_LANGUAGES`) تغییر دهید.

## محدودیت‌ها و نکات مهم برای استفاده‌ی واقعی/تولیدی

این نسخه یک **نمونه‌ی اولیه‌ی کاربردی (MVP)** است، نه یک محصول نهایی صنعتی.
نکاتی که باید بدانید:

1. **دقت تشخیص ناحیه‌ی پلاک**: روش فعلی (Haar Cascade + لبه‌یابی کلاسیک)
   برای شرایط نوری خوب و زاویه‌ی نسبتاً روبه‌رو مناسب است، ولی در نور کم،
   زاویه‌ی تند یا سرعت بالای خودرو دقت کمتری دارد. برای دقت صنعتی،
   توصیه می‌شود `detect_plate_regions` در `detector.py` را با یک مدل
   یادگیری عمیق آموزش‌دیده (مثلاً YOLOv8 fine-tune شده روی دیتاست پلاک
   ایران) جایگزین کنید؛ چون خروجی هر دو یک لیست از مستطیل‌هاست،
   بقیه‌ی برنامه بدون تغییر کار می‌کند.
2. **سرعت OCR روی CPU**: EasyOCR روی CPU نسبتاً کند است. برای فریم‌ریت
   بالاتر، یا از GPU استفاده کنید (`gpu=True` در `ocr_reader.py`) یا
   فاصله‌ی پردازش فریم‌ها را در `config.py` (`FRAME_PROCESS_INTERVAL`) افزایش دهید.
3. **جنبه‌ی حقوقی/حریم خصوصی**: ثبت پلاک خودرو، و به‌ویژه تشخیص و ثبت
   عکس افراد با قابلیت خط/محدوده هشدار، در بسیاری از کشورها و استان‌ها
   مشمول قوانین حریم خصوصی و نظارت تصویری است. پیش از نصب در محل عمومی
   (پارکینگ، ورودی ساختمان، خیابان)، از مطابقت با مقررات محلی (نصب
   تابلوی اطلاع‌رسانی دوربین، مدت نگه‌داری داده و غیره) مطمئن شوید.
4. **دقت تشخیص عبور**: مدل YOLOv4-tiny برای سبک و سریع بودن انتخاب شده
   (اجرا روی CPU معمولی، بدون نیاز به کارت گرافیک)، اما در نور بسیار کم،
   اشیای خیلی کوچک/دور، یا ازدحام زیاد، دقتش نسبت به مدل‌های بزرگ‌تر
   (مثل YOLOv8 کامل) کمتر است. در دیتاست COCO که این مدل با آن آموزش
   دیده، کلاس جداگانه‌ای برای «تریلی» وجود ندارد؛ به همین دلیل تریلی هم
   زیر دسته‌ی «کامیون/تریلی» شناسایی می‌شود. اگر دقت بیشتری لازم دارید،
   `object_detector.py` را می‌توان با یک مدل قوی‌تر (مثل YOLOv8) جایگزین
   کرد؛ چون خروجی هر دو یک لیست از دسته/جعبه است، بقیه‌ی برنامه
   (`centroid_tracker.py`, `worker.py`) بدون تغییر کار می‌کند.
5. **کالیبراسیون ردیابی**: اگر اشیاء خیلی سریع حرکت می‌کنند یا فاصله‌ی
   پردازش (`ZONE_PROCESS_INTERVAL` در `config.py`) زیاد است، ممکن است
   ردیاب نتواند جابه‌جایی بین دو فریم را به همان شیء نسبت دهد و در نتیجه
   عبور ثبت نشود. `TRACKER_MAX_DISTANCE` را متناسب با سرعت اشیاء و
   `ZONE_PROCESS_INTERVAL` را کاهش دهید تا ردیابی روان‌تر شود (به قیمت
   مصرف پردازشی بیشتر).

## توسعه‌های پیشنهادی بعدی
- افزودن یک API ساده (مثلاً با FastAPI) برای مشاهده‌ی آنلاین لیست پلاک‌های ثبت‌شده
- اتصال به سامانه‌ی راهبند/گیت پارکینگ برای باز کردن خودکار در صورت تطبیق پلاک با لیست مجاز
- جایگزینی تشخیص‌گر پلاک با مدل YOLO برای افزایش دقت در شرایط سخت (شب، باران، زاویه)
- اعلان آنی (نوتیفیکیشن تلگرام/ایمیل/پیامک) هم‌زمان با ثبت هر رویداد عبور
